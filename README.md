# Synthetic Mental Health Data Generation

Generating privacy-safe synthetic tabular data from NHANES mental health survey
records with a from-scratch VAE and CTGAN, audited against two SDV baselines.

---

## Overview

Sharing sensitive health data across institutions is legally and ethically
constrained, even when the data is nominally anonymised. Learning the statistical
distribution of real data and releasing a synthetic twin is the usual answer — but
"it looks like the real data and no row is close to a real person" is not a privacy
guarantee.

This project builds four generators and puts each through a **Four-Axis Audit**:
statistical fidelity, downstream utility, nearest-neighbour privacy, and membership
inference. Every axis is *holdout-calibrated* — the question is never "is synthetic
data close to the training data" but "is it closer than a real holdout sample is".
Everything runs across 5 seeds (4 models × 5 seeds = 20 runs).

The headline result is that **holdout calibration is not enough to make DCR a privacy
gate.** Sweeping a kernel-density generator across its bandwidth — the one thing that
varies — produces a generator that *passes* the calibrated DCR gate (ratio 1.05) while a
validated membership attack reads AUC 0.60 at 4.5× chance TPR. Along the same sweep the
DCR ratio rises monotonically while marginal fidelity falls: **DCR rewards infidelity**,
demonstrated within one model family rather than inferred across architectures.

On the four real generators the same attack finds nothing (AUC ≈ 0.50), and that null
survives a 12.5× sweep in released-record count — so it is a property of the generators,
not of an underpowered attack. Meanwhile a real-vs-synthetic distinguishability
classifier reads 0.99 on the identical data. The two are not the same measurement, and
only one of them is a membership attack.

## Dataset

| Source | Type | Rows | Target |
|---|---|---|---|
| NHANES (DPQ, DEMO, MCQ, SLQ, ALQ, DR1TOT) | Tabular survey | ~8,965 PHQ-9 completers | `Depression_Severity`, 5-class (0–4) |

23 features (13 binary/categorical, 10 continuous), all MinMax-scaled to [0,1].
`PHQ9_RAW` (the PHQ-9 sum) and all 9 raw DPQ items are dropped before training — they
are deterministic functions of the target and leaving them in makes utility evaluation
meaningless. The enforced guard is the per-item DPQ assert in `preprocess.py`.

### Getting the data

Raw `.xpt` files are not tracked. Download all six from the **NHANES 2017–March 2020
pre-pandemic** cycle and place them in `data/raw/`:

| File | NHANES component |
|---|---|
| `P_DPQ.xpt` | Questionnaire → Mental Health - Depression Screener |
| `P_MCQ.xpt` | Questionnaire → Medical Conditions |
| `P_SLQ.xpt` | Questionnaire → Sleep Disorders |
| `P_ALQ.xpt` | Questionnaire → Alcohol Use |
| `P_DEMO.xpt` | Demographics |
| `P_DR1TOT.xpt` | Dietary → Day 1 Total Nutrient Intakes |

<https://wwwn.cdc.gov/nchs/nhanes/search/datapage.aspx?Cycle=2017-2020>

### What a fresh clone does and does not contain

Tracked: all source, the paper and its three figures, and the 184 compact result CSVs under
`evaluation/results/` — every number quoted in the paper traces to one of them.

Not tracked, and regenerated in this order:

| Artifact | Regenerated by | Roughly |
|---|---|---|
| `data/processed/` (splits + scaler) | `python preprocess.py` | seconds |
| `models/saved/` (20 checkpoints) | `python run_all_seeds.py` | hours on CPU |
| `data/synthetic/` (row-level output) | `python run_all_seeds.py` | with the above |
| `evaluation/plots/`, `evaluation/results/*.npy` | the audit, as a side effect | with the above |

`scripts/check_consistency.py` needs `data/processed/` **and** `data/synthetic/` present — it
recomputes each metric from the synthetic rows on disk, so it cannot run on a bare clone.

## Models

| Model | Kind | Key feature |
|---|---|---|
| VAE | from scratch (PyTorch) | Column-type-aware decoder, KL annealing, joint label generation |
| CTGAN | from scratch (PyTorch) | WGAN-GP, one-hot class conditioning, 5 critic steps per generator step |
| TVAE | SDV baseline | Deep-learning reference point |
| Gaussian Copula | SDV baseline | Near-zero-cost statistical floor |

## Four-Axis Audit

| Axis | Gating metric | Threshold |
|---|---|---|
| 1 — Fidelity | Mean per-column effect size (KSComplement / 1−TVD) | ≥ 0.90 |
| 2 — Utility | TSTR / TRTR macro AUC ratio (RandomForest) | ≥ 0.85 |
| 3 — NN privacy | DCR(synthetic→train) / DCR(holdout→train) | ≥ 1.00 |
| 4 — MIA privacy | DOMIAS density-ratio attack ROC AUC | ≤ 0.55 |

A generator passes only if all four axes pass. Also reported but non-gating:
LogisticRegression utility variant, classifier-based DOMIAS variant, classifier
two-sample test, and clinical-signal preservation flags.

Axis 4 is only trustworthy after `evaluation/attack_validation.py` passes its
positive control (noisy copies of training rows — the attack must fire) and negative
control (fresh real records — it must not).

## Quick Start

```bash
pip install -r requirements.txt

# 1. Preprocess raw NHANES XPT files -> data/processed/
python preprocess.py

# 2. Validate the Axis-4 attack before trusting any privacy number
python evaluation/attack_validation.py

# 3. One-seed smoke test of all 4 models
python scripts/smoke_test.py

# 4. Full matrix: train (if no checkpoint) + generate + audit, 4 models x 5 seeds.
#    Prints the final mean+/-std comparison table.
python run_all_seeds.py

# 5. Guard against stale results before quoting any number
python scripts/check_consistency.py

# 6. Paper figures (needs all 20 result CSVs present)
python paper/figures/make_figures.py
```

Single model / single seed:

```bash
python models/vae/train.py --seed 42
python models/ctgan/train.py --seed 42
python generate.py --model vae --seed 42 --n 1000      # --model accepts vae|ctgan

# One axis against an already-generated synthetic CSV
python evaluation/statistical.py --model vae --seed 42
python evaluation/utility.py     --model vae --seed 42
python evaluation/privacy.py     --model vae --seed 42
```

`run_all_seeds.py` **skips training when a checkpoint exists.** After changing a
model, `preprocess.py`, or a hyperparameter, delete `models/saved/` and
`data/synthetic/` or you will silently audit old weights.

See `CLAUDE.md` for architecture details, hyperparameters, frozen results, and the
project's known pitfalls.
